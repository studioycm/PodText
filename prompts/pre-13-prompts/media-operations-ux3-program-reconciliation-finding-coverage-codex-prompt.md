## Mission

Restore one truthful, outcome-focused plan for completing the PodText Media
Operations UX.

The product goal is not to produce more research for its own sake. The goal is
to let an operator understand the Media inventory, choose or acquire the right
image, safely inspect and operate on an existing file, resolve actionable
problems, understand the result and continue their work without losing context.

This task makes that goal executable by ensuring that every material design
requirement, browser finding, current-product gap and operator decision has one
explicit owner and cannot disappear silently between UX research, design
selection, technical audit, implementation and outcome review.

This is one documentation-only reconciliation task. It does not redesign or
implement the next interface.

## Literal outcome

At completion, the repository must contain one canonical Media Operations UX3
program document that:

1. states what Media operators need to achieve and the operation hierarchy
   required to achieve it;
2. distinguishes delivered behavior, accepted design, open findings,
   historical proposals, evidence gaps and Package 5-only capabilities;
3. assigns every remaining material finding to one bounded outcome;
4. fixes the serial delivery route for Mini-tasks 3A, 3B, 3C and a later
   freshly researched/replanned Mini-task 4 without pre-designing them;
5. makes the Mini-task 4 dependency on completed 3A–3C contracts impossible to
   miss; and
6. provides a coverage ledger in which every finding ends in an explicit
   terminal disposition rather than silently disappearing.

The operator reviews and accepts this program reconciliation before any
Mini-task 3A task is created or started.

## Required method: Operations UX before solution labels

Use `$ux-design-thinking` and its canonical
`.ai/skills/ux-design-thinking/SKILL.md` package for this reconciliation.

Use it to:

- inventory and classify evidence;
- frame user goals, jobs, operations and interface/surface boundaries;
- expose assumptions and unanswered questions;
- test hierarchy, continuity, action/result and safety contracts;
- trace findings to outcomes and dependencies; and
- lens-lint the proposed program so a Media example, inherited task label or
  implementation artifact does not become the thinking model.

For every interface family or operation, begin with:

1. What does the operator need to achieve?
2. What information, decision, action and result are needed to finish that job?
3. Where does the operator enter, what context must persist, and where must
   they return?
4. Which operation is primary, secondary, destructive, unavailable or future?
5. What must be truthful during empty, busy, partial, failed, blocked,
   interrupted and successful states?
6. Which current authority can perform the action, and which desired action is
   not yet authorized?

Apply the skill proportionately to program reconciliation. Do not run a full
interface-design project, create mockups, generate design assets or select
components in this task. The skill’s optional worked example is
non-authoritative and must not supply Media-specific lenses, vocabulary,
workflow stages, states or conclusions.
